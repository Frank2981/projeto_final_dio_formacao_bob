1 — Visão Geral do Projeto

O DIO Explorer é um assistente inteligente construído sobre o IBM Bob para explorar as trilhas de aprendizagem da plataforma DIO (Digital Innovation One). O projeto foi desenvolvido como trabalho final da Formação Bob, demonstrando na prática os conceitos de Slash Commands, MCP Servers, testes automatizados e integração com dados estruturados.

3 — Slash Commands

Slash Commands são arquivos .md em .bob/commands/ que ensinam ao Bob como responder a um comando específico acionado pelo usuário com /nome-do-comando.

/trilha <tecnologia>

Consulta a trilha de uma tecnologia no JSON e formata um plano de estudos completo em Markdown.

CampoDescrição
Arquivo.bob/commands/trilha.md
Argumento$1 = nome da tecnologia (ex: Java, Python)
Fonte de dadosdio_explorer/data/trilhas_dio.json
SaídaPlano de estudos: módulos, badges, lives, promoções
Exemplo de uso
/trilha Java
/trilha Python
/trilha React

/desafio <tecnologia> <nivel>

Gera um desafio de código aleatório, criativo e educativo para a tecnologia e nível especificados.

CampoDescrição
Arquivo.bob/commands/desafio.md
Argumentos$1 = tecnologia · $2 = nível (Básico / Intermediário / Avançado)
XPBásico: 500–1500 · Intermediário: 1500–3000 · Avançado: 3000–5000
SaídaDescrição, requisitos, entrada/saída, dicas, casos de teste, recompensa
Exemplo de uso
/desafio JavaScript Intermediário
/desafio Python Básico
/desafio Go Avançado

/certificado <nome> <trilha>

Gera um certificado fictício e bem formatado de conclusão de trilha DIO, com ID único, competências e link de verificação.

CampoDescrição
Arquivo.bob/commands/certificado.md
Argumentos$1 = nome do aluno · $2 = nome da trilha
ID geradoFormato DIO-CERT-XXXXXXXX (8 chars alfanuméricos)
SaídaCertificado completo com tabela, competências, assinaturas e link
Exemplo de uso
/certificado "Maria Silva" "Formação Java Developer"
/certificado João Python

6 — Prompts Utilizados com Bob

Esta seção documenta os principais tipos de prompts aplicados durante o desenvolvimento do projeto, com exemplos reais e análise de cada abordagem.

6.1 — Criação do dataset

Prompt
Gere um arquivo JSON com 30 trilhas da DIO. Cada trilha deve ter: id, nome, tecnologia, nivel (Básico/Intermediário/Avançado), numero_de_modulos, xp_total, badges_disponiveis (array), promocoes (objeto ou null), vitalicio (boolean) e live_ao_vivo (objeto com disponivel, frequencia, dia_hora).
Por que funciona
Especificar o schema exato e os tipos de cada campo no prompt elimina a ambiguidade. Bob gera JSON válido e pronto para uso sem iterações corretivas.

6.2 — Criação do módulo de negócio (trilhas.js)

Prompt
Crie o arquivo dio_explorer/src/trilhas.js em CommonJS com as funções: carregarTrilhas(), buscarTrilhaPorTecnologia(), listarTecnologias(), gerarPlanoDeEstudos(), calcularXpDesafio(), calcularTempoDesafio(), gerarIdDesafio(), gerarDesafio(), gerarIdCertificado(), formatarData(), gerarCertificado(). Cada função deve ter JSDoc. A busca de trilha deve ser case-insensitive e suportar match parcial.
Por que funciona
Listar todas as funções esperadas com seus comportamentos (case-insensitive, match parcial, JSDoc) em um único prompt garante que o código seja gerado completo e testável desde a primeira versão.

6.3 — Criação dos Slash Commands

Prompt
Crie o slash command /trilha em .bob/commands/trilha.md. Ele deve receber $1 (tecnologia), ler o arquivo trilhas_dio.json e formatar um plano de estudos em Markdown com seções de módulos, badges, lives e promoção. Se não encontrar a trilha, deve listar as disponíveis.
Por que funciona
Slash Commands são arquivos de instrução — ao especificar o template de saída e o comportamento de fallback no prompt, você define o contrato completo de comportamento do comando.

6.4 — Criação do servidor MCP (TypeScript)

Prompt
Crie um servidor MCP em TypeScript em dio_explorer/mcp/src/index.ts usando @modelcontextprotocol/sdk e zod. Exponha as ferramentas: listar-trilhas, buscar-trilha (param: tecnologia), gerar-plano, gerar-desafio (params: tecnologia, nivel com enum), gerar-certificado (params: nome_usuario, nome_trilha). Use StdioServerTransport e importe a lógica de trilhas.ts.
Por que funciona
Citar as dependências exatas (sdk, zod, StdioServerTransport), os nomes dos parâmetros e o tipo enum para nivel elimina decisões abertas que causariam inconsistências na geração.

6.5 — Criação dos testes unitários

Prompt
Crie trilhas.test.js com testes unitários para todas as funções exportadas de trilhas.js usando Node.js puro, sem dependências externas. Cobertura-alvo ≥ 70%. Inclua um mini test runner com assert() e assertThrows(), suites por função, e relatório final com total/aprovados/reprovados/cobertura%.
Por que funciona
Pedir "sem dependências externas" e especificar a meta de cobertura gera testes prontos para rodar com node sem npm install, reduzindo atrito para novos usuários do projeto.

6.6 — Conversão para PowerShell

Prompt
Converta trilhas.test.js para PowerShell em trilhas.test.ps1. Recrie toda a lógica de busca, XP, tempo, IDs e formatação de data em PowerShell puro. Mantenha as mesmas suites e asserts. Adicione relatório final equivalente.
Por que funciona
Ao pedir para "recriar a lógica" em vez de "converter diretamente", você obtém código idiomático na linguagem alvo, em vez de JavaScript-translated-to-PowerShell que não funciona.

8 — Dicas de Uso com Bob

Dica 1 — Slash Commands vs Chat livre
Use Slash Commands (/trilha, /desafio, /certificado) para operações diretas e predefinidas. Use o chat livre quando quiser que Bob interprete sua intenção e escolha a MCP Tool correta automaticamente.
Dica 2 — Modo Agent para gerar código
Sempre use o Modo Agent (padrão) para criar, editar e refatorar arquivos. O Modo Plan é ideal para planejar antes de implementar. O Modo Ask é para perguntas conceituais sobre o Bob ou IBM.
Dica 3 — Seja específico no schema
Ao pedir para Bob gerar dados ou código, inclua o schema exato: tipos, nomes de campos, valores de enum, comportamentos de fallback. Quanto mais específico, menos iterações você precisa.
Dica 4 — MCP Server para integração real
O servidor MCP transforma suas funções em ferramentas que o próprio Bob pode chamar automaticamente durante uma conversa. Registre o servidor em .bob/mcp.json e Bob usa as tools sem você precisar invocar manualmente.
Dica 5 — Testes sem dependências externas
Para projetos educacionais ou que precisam ser executados facilmente, peça testes em Node.js puro (sem Jest, Mocha, etc.). Isso elimina a necessidade de npm install para validar o código.
Dica 6 — update_todo_list para tarefas longas
Em tarefas complexas com várias etapas, Bob usa o update_todo_list internamente para rastrear progresso. Você pode pedir explicitamente: "crie um plano de tarefas antes de implementar" para ter visibilidade de cada passo.

9 — Insights para Futuros Profissionais

Sobre construir com IA (Bob / LLMs em geral)

Insight 1 — Prompts como especificações técnicas
Um prompt bem escrito é equivalente a uma especificação técnica. Inclua: o que deve ser feito, o formato de entrada/saída, as restrições (sem dependências externas, case-insensitive, etc.) e o comportamento de erro. Projetos gerados com prompts vagos geram código vago.
Insight 2 — Minimal change principle
Bob segue o princípio de "menor mudança que resolve o problema". Não espere que ele adicione features não pedidas. Se quiser algo, peça explicitamente. Isso mantém o código limpo e rastreável.
Insight 3 — MCP é o futuro da extensibilidade
O Model Context Protocol permite que qualquer ferramenta externa seja integrada ao Bob (ou qualquer LLM compatível). Aprender a construir MCP Servers te permite criar integrações com APIs, bancos de dados, sistemas legados e serviços internos de forma padronizada.
Insight 4 — Slash Commands = automação de workflows
Slash Commands no Bob são arquivos Markdown que ensinam comportamento. Isso é extremamente poderoso: você pode criar comandos personalizados para seu time, empresa ou projeto sem escrever uma linha de código de interface.
Insight 5 — Dados estruturados potencializam IAs
O JSON de trilhas foi o "combustível" que tornou todos os comandos possíveis. IAs performam melhor quando têm dados estruturados e bem tipados. Investir tempo em modelar bem o dado inicial multiplica a qualidade de tudo que vem depois.
Insight 6 — Testes são a prova de que funciona
O projeto tem 100% de aprovação em 39 testes. Isso não foi acidente — os testes foram planejados com cobertura por suite e casos de edge case explícitos. Em projetos com IA gerando código, testes são ainda mais críticos para garantir que o comportamento está correto.
Insight 7 — Portabilidade importa
O projeto roda em Node.js puro E em PowerShell, com stdio E HTTP. Essa portabilidade amplia o alcance: Windows, Linux, Mac, local, remoto. Ao projetar ferramentas, pense sempre em quem vai usar e em qual ambiente.
Insight 8 — Documentação é parte do produto
README, JSDoc, comentários de seção, relatórios de teste — tudo isso é documentação. Para quem vai aprender com este projeto, a documentação é o produto principal. Código sem documentação tem metade do valor.

11 — Como Executar o Projeto Completo

Clone o repositório e abra no Bob

Abra a pasta projeto_final_dio_formacao_bob como workspace no IBM Bob.

Instale as dependências do MCP Server

cd dio_explorer/mcp && npm install

Compile o TypeScript (opcional — build já incluso)

npm run build — gera os arquivos em build/

Confirme o registro do MCP em .bob/mcp.json

O arquivo já aponta para ${workspaceFolder}/dio_explorer/mcp/build/index.js. Recarregue o Bob para ativar.

Execute os testes unitários

node dio_explorer/src/trilhas.test.js — todos os 39 testes devem passar com 100%.

Use os Slash Commands ou chat livre

Tente /trilha Java, /desafio Python Básico ou "Liste todas as trilhas da DIO" no chat do Bob.
